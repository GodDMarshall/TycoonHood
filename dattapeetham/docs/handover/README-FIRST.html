Look at the website now

  1. Install Node.js (free) from nodejs.org: the LTS version, 20 or newer, with the default options. You only need it on this computer, for the preview. The live website does not need it.

  2. Extract the whole zip first (right-click it, then Extract All): the preview does not run from inside the zip. Then open the preview folder and double-click Start-Preview.cmd. (On a Mac or Linux: run ./start-preview.sh in a terminal.)

  3. Your browser opens the site. The black window also shows an address for a phone or tablet on the same Wi-Fi. Keep the window open while you look; close it to stop.

Without Node.js you can still open website/index.html directly: the pages show, but site search does not work that way.

The one thing to know first

The existing booking platform must move before the switch

Today www.dattapeetham.org is the Peetham's existing platform: puja bookings, donations, sign-in, the store and the concert bookings. The new website does not replace it; it links to it.

So before the new website takes over www.dattapeetham.org, the platform must also answer at its own address, for example seva.dattapeetham.org (the name is the Peetham's choice). The website is then rebuilt with that address, so that every "Book a Puja" and "Donate" button points there.

Look in VERSION.txt: if it shows a WARNING that both addresses are the same, the website folder is ready for previewing, but not yet for taking over the domain.

What it needs to run

The website is a folder of ready-made files. Running it needs far less than the existing platform does. Prices depend on the host and the plan you choose; this page does not quote any.

Hosting

Any web host that serves files over HTTPS: ordinary shared hosting (cPanel), a server of your own (Apache, nginx or IIS), or a static host (Netlify, Cloudflare, Vercel). Nothing is installed on the server: no database, no PHP or Node.js, no server-side code.

Space

Under 1 GB. VERSION.txt gives the exact size of the website folder; almost all of it is photos.

Traffic

Measured on version 1.0.0: a visitor who reads one page to the end downloads about 0.5 to 2.5 MB from your host (the home page is the largest). Browsers keep photos and code, so a returning visitor downloads much less.

Certificate

One HTTPS certificate for www.dattapeetham.org and dattapeetham.org. Let's Encrypt issues them free of charge, and many hosts set one up for you.

Outside services

Google Fonts, the Google Maps embed and the YouTube player. The site uses them without any account or API key.

The platform

The existing platform keeps running with its own vendor, as today. It moves to a new address, which needs its own HTTPS certificate.

Upkeep

Someone updates events and temple hours, rebuilds and uploads (a computer with Node.js; see the maintenance guide). The events listed today end on 23 December 2026; the next year's calendar then needs to be added, which is a job for a developer.

What the Peetham decides

Nobody else can settle these. Each has a line in the launch checklist.

  • The platform's new address, who moves the platform, and when. The Peetham, with the platform's vendor
  • Where the new website is hosted. The Peetham, with its IT person
  • The switch date, and who may call it off and switch back. The Peetham
  • The open questions about content: timings, dates and counts on which the official pages disagree. The Ashram
  • A fluent reviewer for each language (Kannada, Hindi, Tamil, Telugu). The translations are machine-assisted; no fluent speaker has yet reviewed them for the Peetham. The Peetham
  • The privacy notice for the new website, and whether the platform's privacy, terms and disclaimer pages also cover it. The Peetham's legal team
  • The photos. Most were small web copies, enlarged with an AI enhancer that sharpens them but can only estimate lost detail. The Ashram checks them, the portraits of Sri Swamiji above all, and sends camera originals where it can. The Ashram
  • Visitor statistics. The website has none. Adding any is a code change and changes what the privacy notice must say. The Peetham
  • Who keeps it current (events, hours, photos), and who supports it after the hand-over. The Peetham, with the agency

Going live in five steps

  1. Review and approve. Read every page. Fluent devotees read the four other languages. The Ashram answers the open questions.

    The Peetham · Launch checklist

  2. Move the existing platform to its own address and check that bookings and payments work there.

    The platform's own team or vendor · Domain cutover, step 2

  3. Rebuild the website for production with the platform's new address.

    Your IT person, or the agency · Domain cutover, step 3

  4. Put it on the server and switch the domain: upload the files, set up the HTTPS certificate, point DNS at the new server.

    Your IT person · Deploy guide and Domain cutover

  5. Check, then tell search engines: run the automatic server check, try a booking and a donation, submit the sitemap.

    Your IT person, with the platform team · Domain cutover, steps 7–8

Step 2 must be finished before step 4. Until the domain is switched, nothing visitors see changes, and the switch can be undone by setting DNS back.

What stays on the existing platform, and why

The new website deliberately has no database, no accounts and no payment handling. These stay where they are, and the website links to them:

  • puja and seva bookings, and donations;
  • sign-in, subscriptions and the store;
  • the Raga Sagara concert bookings;
  • the privacy policy, terms and disclaimer;
  • the full calendar and the archives the website cites as sources.

They handle money and devotees' personal details, which need a server, a database and a payment gateway. The platform already does this, and its records are there. The legal pages are the Peetham's own documents: the agency does not write legal text.

The contact form sends nothing to a server

It opens the visitor's own e-mail app with the message ready, addressed to mail@dattapeetham.com. Nothing leaves until the visitor presses Send there.
